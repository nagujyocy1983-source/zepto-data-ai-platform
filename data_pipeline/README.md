# Module 1 — Data Pipeline

## Zepto Data & AI Platform

This module implements the data ingestion and storage pipeline for the Zepto Data & AI Platform capstone project.

The pipeline performs the following steps:

1. Scrape book data from Books to Scrape
2. Clean and transform the scraped data
3. Convert GBP prices to INR using the fixed project rate
4. Save the cleaned dataset as CSV
5. Store the data in a normalized SQLite database
6. Execute SQL analysis queries
7. Verify SQL JOIN results using pandas

---

## 3. Data Cleaning and Transformation

Data cleaning is implemented in:

```text
data_pipeline/pipeline.py

```
The cleaning process performs the following transformations:

- Removes the `£` currency symbol from GBP prices and converts them to `float`.
- Converts star-rating words (`One` to `Five`) into integer ratings from 1 to 5.
- Converts availability text into a Boolean `in_stock` field.
- Converts GBP prices to INR using the fixed project rate:

`1 GBP = 105.50 INR`

- Removes the original text-based `availability` column after conversion.
- Handles numeric parsing failures using median imputation.
- Ensures the final rating column contains integer values from 1 to 5.

## 4. Database Design

The database implementation is in:

```text
data_pipeline/database.py
```

The SQLite database is:

```text
data_pipeline/zepto_catalog.db
```

The database uses a normalized two-table design.

### Categories table

The `categories` table stores unique book categories.

```text
categories
-----------
category_id     PRIMARY KEY
category_name   UNIQUE
```

### Books table

The `books` table stores the cleaned book records.

```text
books
-----
book_id         PRIMARY KEY
title
price_gbp
price_inr
rating
in_stock
category_id     FOREIGN KEY
```

The `category_id` column in the `books` table references the `category_id` primary key in the `categories` table.

The database relationship is:

```text
categories
    |
    | category_id
    |
    v
books
```

This normalized structure separates category information from book information and demonstrates a primary-key/foreign-key relationship.

### Database loading

The cleaned CSV data is loaded into the SQLite database using Python and SQLite.

The database creation process also verifies:

- Sample records
- Relationship between categories and books

## 5. SQL Analysis

The SQL queries are stored in:

```text
data_pipeline/queries.sql
```

The project contains five SQL queries that demonstrate the required SQL operations.

### Query 1 — Distinct Categories

Demonstrates:

- `SELECT`
- `DISTINCT`
- `ORDER BY`

The query lists all unique book categories in alphabetical order.

### Query 2 — Books Within a Price Range

Demonstrates:

- `SELECT`
- `WHERE`
- `BETWEEN`
- `ORDER BY`
- `LIMIT`

The query retrieves books with GBP prices between 20 and 40, ordered from highest to lowest price.

### Query 3 — Highly Rated Books

Demonstrates:

- `SELECT`
- `WHERE`
- `IN`
- `ORDER BY`
- `LIMIT`

The query retrieves books with ratings of 4 or 5 stars.

### Query 4 — Category-Level Analysis

Demonstrates:

- `JOIN`
- `GROUP BY`
- `COUNT`
- `AVG`
- `ORDER BY`

The query joins the `categories` and `books` tables and calculates the number of books and average GBP price for each category.

### Query 5 — Most Expensive Books

Demonstrates:

- `JOIN`
- `ORDER BY`
- `LIMIT`

The query joins the two tables and returns the ten most expensive books along with their category names.
